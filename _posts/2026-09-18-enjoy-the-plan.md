# Enjoy the Plan

My job has changed a lot in the past year. Twelve months ago I still wrote code by hand, the way I had done for years. I liked writing code; writing code was the whole reason I fell into this career. It was pure creative problem solving.

Today, as I fired up IntelliJ to trace through some code, I found myself reflecting on how long it's been since I've written any substantial amount of code by hand. It's been several months, maybe six. For other developers it's probably longer, as I was a bit of a reluctant adopter. These days I exclusively use Claude Code to write code, as do my peers. If you had told me this a year ago, I would have said that was ridiculous and if true a damn shame. It'd be like turning an artisan into a factory worker.

Indeed, there are moments where my hard-won skills feel useless in a world where Claude Code exists. But there are other moments where my skills still feel essential: for instance, when I catch Claude doing something profoundly dumb, or when I need to nudge it into using a better pattern. Often it's because I have context the LLM does not: like such-and-such service we are trying to call has bad reliability, so we should use retries with an exponential backoff, but jitter is not necessary because there is really no thundering herd. Or such-and-such fancy pattern the LLM recommends is not necessary because this code is a short-term fix on account of the repo being deprecated. Instead of dealing directly with code, I'm increasingly dealing with context.

Which brings me to my new mantra: **Enjoy the Plan**.

I didn't always read the plan generated by Claude; I often just skimmed it. It's not super enjoyable to read a super dense plan file in a terminal. I skimmed to get the gist of it, maybe made some corrections to obvious flaws, and hit approve. But recently I wrote a tool to open the plan in a browser window, nicely formatted in rendered Markdown. And now I slow down and read the entire plan. This has some benefits, as you might imagine!

The most obvious benefit is that you catch more errors. As good as Claude is, it still makes bad decisions, from flawed business logic to how it splits the work into PRs. How often have you had it revise something obvious, or have to close PRs because Claude screwed them up? Only for those corrections to take way longer than they should.

The subtler benefit of reading the plan is that you regain control, and your skills matter again. The plan is for *you* to read. And yes, it is long and dense, but you are the operator. You can shape the implementation however you like, you can discard it entirely. It's here that you can still exercise your creativity and judgement in having the LLM adhere to an architecture &mdash; your architecture &mdash; that will scale well. It's here that my job is still fun, though it's a different fun than coding.

As I said, my job has changed a lot in the last year. Now the essential skill is managing context &mdash; which, when you think about it, is really just critical thinking. And though the LLM *seems* to want to move fast, it only needs to move as fast as you need. Slow down, read the plan, think about the plan, shape the plan. The developer in the loop is still supreme, but only if they want to be. Enjoy the plan!
